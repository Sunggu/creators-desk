# 의사결정 일지 (ADR): 제품 방향성 단일화 및 웹 옵시디언 에디터 결정

> 일자: 2026-10-03  
> 상태: 승인 (Approved)  
> 참여자: 프로젝트 리더, 개발 에이전트  

---

## 1. 배경 및 문제 상황 (Context)

- 이전 로드맵에서는 "방해 없는 범용 집필 도구", 클라우드 백엔드 권위, 크롬 익스텐션 클리핑, AI 지적 엔진 플러그인, CRDT 오프라인 병합 등 광범위하고 복잡한 요구사항이 나열되어 있었음.
- 이로 인해 제품의 핵심 가치가 분산되고 개발 우선순위가 불명확해지는 문제 발생.
- 명확하고 직관적인 단일 핵심 목표로의 집중이 필요했음.

---

## 2. 핵심 결정 사항 (Decisions)

### ① 제품 목표 단일화: "웹 기반 순수 옵시디언 에디터"
- 제품의 목표를 **"옵시디언 에디터 기능을 웹으로 순수하고 쉽게 옮긴다"** 하나로 정의함.
- 복잡한 AI, 외부 백엔드 연동, 익스텐션 등 부가 기능은 배제하고 순수 마크다운 편집 경험에 집중.

### ② 프로젝트 단위 = Vault
- 모든 작업의 최상위 단위는 **Vault**임.
- **첫 진입 플로우**:
  - 첫 화면에서 사용자가 보유한 Vault 목록을 확인하고 선택/생성 가능.
  - 이전에 열어둔 Vault가 있다면(`lastActiveVaultId`), 접속 시 자동으로 해당 Vault 작업 공간으로 진입 (브라우저 저장소 활용).

### ③ 에디터 코어: CodeMirror 6 (CM6)
- 실제 옵시디언과 동일한 **CodeMirror 6** 엔진 채택.
- 리치 텍스트 AST(TipTap 등) 대신 **순수 마크다운 텍스트가 Single Source of Truth**가 되는 아키텍처 유지.
- 향후 인라인 Live Preview(위지윅 장식)와 `[[WikiLink]]` 확장이 용이함.

### ④ 데이터 영속성 (Client-First Storage)
- **IndexedDB**: Vault 목록, 폴더 및 마크다운 파일 내용 보관.
- **localStorage / Cookie**: 최근 활성 Vault ID (`lastActiveVaultId`) 등 세션성 상태 보관.

---

## 3. 구현 단계 (Phases)

1. **Phase 1: Vault 관리 & 세션 복구** (기본 저장소, Vault 선택기 화면)
2. **Phase 2: Vault 파일 트리 탐색기** (폴더/파일 탐색 및 생성/수정/삭제)
3. **Phase 3: 마크다운 에디터 코어** (CM6 연동, 실시간 자동 저장, 문법 스타일링)
4. **Phase 4: 옵시디언 특화 기능** (Live Preview 인라인 데코레이션, 위키링크)

---

## 4. 결과 및 영향 (Consequences)

- 기술적 불확실성이 해소되고 아키텍처가 단순 명료해짐.
- 브라우저 로컬 우선으로 동작하므로 복잡한 서버 인프라 구축 없이 즉시 유의미한 제품 빌드가 가능함.
